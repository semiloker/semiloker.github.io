Devlog

This devlog documents the development process, architectural decisions, mistakes, experiments, and technical findings.

Introduction

This project started as a small technical experiment and slowly evolved into a full engine prototype.

The devlog focuses on documenting real development instead of presenting a polished success story.

Engine

Core architecture, low-level systems, and platform-specific decisions.

Project structure

The repository is organized to keep runtime data, build artifacts, and dependencies clearly separated.

The bin directory contains runtime output, while build is fully disposable.

Build system

CMake is used as the main configuration layer to handle cross-platform compilation.

Dependencies

External libraries are managed via git submodules to ensure strict version consistency.

We use GLAD for OpenGL loading and GLM for math operations.

Graphics

Rendering pipeline, shader management, and visual fidelity systems.

OpenGL

The renderer is built on top of OpenGL 4.5, utilizing DSA (Direct State Access) to reduce driver overhead.

State caching is implemented to avoid redundant API calls during the render loop.

Assets

Asset hot-reloading is supported for shaders and textures in debug mode.

Textures are compressed into custom binary formats for faster loading times.

Future plans

Roadmap for the upcoming quarters and experimental features.

Scripting

Planning to integrate Lua for high-level gameplay logic to separate engine code from game mechanics.
