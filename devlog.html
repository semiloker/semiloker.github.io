Devlog

Development log for Pixora — a modern 3D game engine built with OpenGL, GLUT, GLEW, and Dear ImGui. This devlog documents the development process, architectural decisions, and technical findings.

Introduction

Pixora started as a learning project to understand modern OpenGL rendering pipelines and evolved into a full-featured 3D engine with SSAO, shadow mapping, and an interactive editor.

The engine is built entirely in C++17 with a focus on clean architecture, reusable components, and real-time scene editing capabilities. All dependencies are included locally for easy setup on Windows.

Current Version: 1.0.0 (Foundation Release)
Last Update: March 2026
Platform: Windows (MinGW-w64), Linux compatible
Graphics API: OpenGL 4.5+

Engine Architecture

Core systems, singleton managers, and the rendering pipeline.

Project Structure

The codebase follows a clear separation between source files, headers, and dependencies. The src/ directory contains all implementation files, while include/ holds the public API headers.

src/ — main.cpp, window.cpp, model_renderer.cpp, shader_manager.cpp, ssao_manager.cpp, fbo_manager.cpp, light_manager.cpp, gizmo.cpp, ui_manager.cpp, text_render.cpp, model_loader.cpp

include/ — Corresponding headers plus bitmap.h, render_stats.h, stb_image.h

dependencies/ — GLEW 2.1.0, FreeGLUT 3.6.0, GLM, imgui-docking, and sample Models (scene.obj with textures)

build/ — Compiled object files (.o). Safe to delete for full rebuild.

bin/ — Final executable (app.exe) and runtime DLLs (glew32.dll, glut.dll)

Singleton Managers

The engine uses the singleton pattern for core systems to ensure global access without passing references throughout the codebase.

Window — Main application window, input handling, camera control, and the game loop. Manages GLUT callbacks and frame timing.

ModelRenderer — GPU mesh management, model instances, light system. Handles both Legacy and Shader render modes.

ShaderManager — Shader program compilation, uniform management. Contains main shader, depth shader, and SSAO shader programs.

FBOManager — Framebuffer object creation for shadow mapping (2048x2048) and off-screen rendering passes.

SSAOManager — Multi-pass SSAO rendering: geometry pass, compute, blur, and upsample. Configurable via SSAOConfig struct.

LightManager — Scene light storage, legacy LightConfig for backward compatibility with older rendering code.

UIManager — Custom immediate-mode UI system with panels, menus, buttons, sliders, and dark theme.

ModelLoader — OBJ/MTL file parsing with vertex hashing, material indexing, and texture path resolution.

Build System

A simple makefile handles compilation with MinGW-w64 on Windows. The build process compiles all .cpp files in src/ to build/, then links them into bin/app.exe.

Compiler: g++ with -std=c++17 -Wall -O2 flags

Include paths: include/, dependencies/glew-2.1.0/include, dependencies/freeglut-3.6.0/include, dependencies/glm

Libraries: -lglew32 -lglut -lopengl32 -lglu32

Targets: make (build), make clean (remove .o), make fullclean (remove .o and .exe)

Dependencies

All third-party libraries are included in the dependencies/ folder for zero-setup compilation on Windows.

GLEW 2.1.0 — OpenGL Extension Wrangler. Handles extension loading for OpenGL 4.5+ features. Pre-compiled libraries included (Release/x64).

FreeGLUT 3.6.0 — OpenGL Utility Toolkit. Window creation, input handling, and main loop management. Provides cross-platform abstraction.

GLM — OpenGL Mathematics. Header-only vector/matrix library with GLSL-like syntax. Used for all 3D math operations.

Dear ImGui (docking) — Inspiration for UI system architecture. The custom UIManager follows ImGui's immediate-mode design patterns.

stb_image.h — Single-header image loading library. Supports PNG, JPG, BMP, TGA, PSD for texture loading.

Graphics & Rendering

Rendering pipeline, shader programs, and post-processing effects.

Rendering Pipeline

The engine supports two render modes: Legacy (immediate-mode OpenGL) and Shader (modern VAO/VBO/EBO with GLSL).

Frame Loop: Input → Camera Update → Shadow Pass → Geometry Pass → SSAO Compute → SSAO Blur → SSAO Upsample → Main Render → UI Render → Present

Shadow Pass: Renders scene from light perspective to 2048x2048 depth texture. Used for shadow comparison in main fragment shader.

Geometry Pass (SSAO): Outputs world-space normals and view-space depth to FBO. Half-resolution for performance (320x180 at 640x360 render).

SSAO Compute: 32-sample random kernel, hemisphere sampling, depth comparison with 0.025 bias. Outputs occlusion factor per pixel.

SSAO Blur: Edge-aware bilateral filter with depthSigma=0.002 and colorSigma=1.0. Smooths noise while preserving depth edges.

SSAO Upsample: Depth-aware or joint bilateral upsampling reconstructs full-resolution SSAO from half-resolution buffer.

Shader Programs

Shaders are compiled from source strings embedded in shader_manager.cpp. The ShaderProgram struct handles compilation, linking, and uniform management.

Main Shader: MVP transformation, normal matrix, Phong lighting with shadows, texture sampling with normal maps.

Depth Shader: Simple light-space MVP transform, depth-only output for shadow mapping.

SSAO Geometry Shader: Vertex: standard MVP. Fragment: outputs world normal and view depth to textures.

SSAO Compute Shader: Fullscreen quad, samples normal/depth texture, computes occlusion with random kernel.

SSAO Blur Shader: Bilateral filter kernel (5x5), weights based on depth and color similarity.

SSAO Upsample Shader: Reconstructs full-res SSAO using depth-aware interpolation from half-res buffer.

SSAO Configuration

SSAO parameters are exposed via SSAOConfig struct and editable in the Debug Panel.

radius: 0.5f — Sample sphere radius around each pixel

bias: 0.025f — Depth bias to prevent self-occlusion artifacts

scale: 1.0f — SSAO intensity multiplier

kernelSize: 32 — Number of random samples (higher = better quality)

depthSigma: 0.002f — Blur filter depth sensitivity

colorSigma: 1.0f — Blur filter color sensitivity

upsampleMode: 0=Depth-Aware, 1=Joint Bilateral

Lighting System

Four light types with configurable properties. Lights are rendered with gizmo handles for interactive editing.

Directional: Infinite distance, parallel rays. Used for sun/moon. Supports shadow mapping.

Point: Omnidirectional from single point. Attenuation with constant/linear/quadratic terms.

Spot: Cone-shaped illumination. innerCutoff/outerCutoff for soft edges. Supports shadows.

Area: Rectangular light source. areaRight/areaUp vectors define orientation. areaWidth/areaHeight for dimensions.

Transformation Gizmos

Blender-style 3D gizmos for object manipulation. Screen-space picking with axis-constrained dragging.

Translate: Colored arrows (X=red, Y=green, Z=blue). Drag to move objects along axes.

Rotate: Circular rings for each axis. Rotation arc visualization with angle display.

Scale: Cube handles on axes. Uniform scaling via universal handle.

Picking: distanceToLineScreen() for arrows, distanceToCircleScreen() for rings. 12-pixel pick radius.

UI System

Custom immediate-mode UI inspired by Dear ImGui.

Architecture

UIManager is a singleton that handles all UI rendering using OpenGL immediate-mode primitives (glBegin/glEnd style with GLUT bitmap fonts).

UIRect: x, y, w, h with contains() hit testing

UIColor: RGBA with fromHex() helper and lerp() interpolation

Theme: Dark ImGui-style colors (bgMain=#1A1A1A, bgChild=#252525, accent=#4A90D9, textNormal=#E0E0E0)

Panels & Widgets

Draggable, resizable panels with collapse/expand functionality. Each panel has a title bar with close button.

Debug Panel (F1): FPS counter, frame timing stats, GPU info, render stats, SSAO settings

Scene Panel: Grid toggle, gizmo visibility, wireframe mode, global ambient light slider

Camera Panel: Camera speed, rotation speed, locked state, position/rotation displays

Light Editor (P): Light list, add/delete lights, property editing (color, intensity, attenuation, shadows)

Performance Panel: Min/max/avg frame times, GPU time queries, draw call counts

Interaction

Mouse-driven interaction with hover/active states. Panel dragging via title bar, resizing via bottom-right corner.

Top Bar: Menu dropdowns with keyboard shortcuts displayed (e.g., "Save [Ctrl+S]")

Context Menus: Right-click popup menus with submenu support

Widgets: Checkboxes, sliders with drag input, toggle buttons, color pickers

Future Plans

Roadmap for v1.1 and beyond.

Version 1.1 — Enhancement

Focus on gameplay systems and visual effects.

Physics Integration: Bullet Physics or NVIDIA PhysX for rigid body dynamics and collision detection

Particle System: GPU compute shader particles for fire, smoke, explosions with custom emitters

Skeletal Animation: Assimp integration for bone-based character animation with keyframe blending

Terrain Rendering: Heightmap-based terrain with LOD geomorphing and texture splatting

Water System: Reflection/refraction textures, Fresnel shading, caustics projection

Version 1.2 — Expansion

Advanced features and platform support.

VR Support: OpenXR integration for stereo rendering and motion controller input

Vulkan Backend: Alternative rendering path using Vulkan API for improved performance

macOS Support: Cross-platform builds for Apple Silicon and Intel Macs

Asset Pipeline: FBX/glTF importers, automated texture compression, material presets

Version 2.0 — Complete Editor

Full game development environment.

Lua Scripting: Embedded Lua VM for high-level game logic separation

Audio Engine: FMOD or Wwise integration with 3D spatial audio

Networking: Client-server architecture for multiplayer game support

Visual Scripting: Node-based programming interface for designers

Animation Editor: Timeline-based animation editing with blend trees
